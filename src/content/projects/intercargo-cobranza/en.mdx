## Context

A collections assistant over WhatsApp for Intercargo's operation in Panama. The client checks their statement, reports a payment or promises a date without leaving the conversation.

It is still in development. Intercargo asked to automate that cycle, because collections tied up its team in repetitive contact and verification work that grew with the receivables book. It wanted debtors to handle the routine part on their own.

## Problem

Collections relied on lists of clients who had to be contacted one by one. Every reminder was a call or a message written by hand, and the order depended on who reviewed the list that day.

A person checked every payment receipt before updating the balance. Until that check, the statement the company saw did not match what the client had already paid.

## Technical decisions

A collections assistant shows third-party balances. If the model decided who sees them, every reply would depend on it not making a mistake, and a language model does not offer that guarantee.

So the model does one thing: turn a plain-language message into an intent and, where relevant, into a date.

Everything else is code: validating identity, querying the receivables book, recording a payment promise and deciding whether a reminder is due. The conversation is resolved in a state machine that returns actions. A separate layer translates those actions to the WhatsApp transport.

The service uses no web framework. It starts a server with `node:http` and is deployed on its own.

It was started before [the corporate platform](/en/projects/intercargo-plataforma), so it carries its own model of the receivables book: customers, invoices, promises and payment reports, across nine tables of its own. Merging it into the platform is outstanding work: the split comes from the order in which the two projects started.

The model provider is swappable, with two implementations behind the same interface.

## Architecture

The model takes part in a single step of the path. What it receives and what it returns are structures the code validates before continuing.

Since the transport sits in a separate layer, the whole conversation can be run without Meta credentials or a WhatsApp line.

## Result

Debtors check their balance and attach their receipt without waiting for the team, which steps in only where judgement is needed.

The server sends the reminders, honours opt-outs and computes working days, so the operation does not depend on someone watching the calendar.

One command replays a whole dialogue against the real logic. It is used to test the hard cases: a promise with an ambiguous date, a payment reported twice and a client asking to stop receiving messages.

## What I learned

That simulator walks the state machine end to end. That is why it detects a flow regression but does not locate it: when it fails, it points at the whole dialogue rather than the module.

Locating the fault requires tests over the action layer, which are the next step.

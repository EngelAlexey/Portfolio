## Context

A tool Kaizen puts in the hands of the companies that license its ERP. They query their own data by writing the question in plain language.

I started it with little experience and rebuilt it from scratch four times. Each version absorbed what the previous one could not handle.

## Problem

Every client question was handled by someone on the support team. As the demand for help grows, that team saturates and the client waits.

A large share of those questions repeat: how to do something, what a human-resources or occupational-health concept means, what labour law says about it. The tool exists so a client resolves those on their own, and the team handles what genuinely needs a person.

## Technical decisions

With several client companies on the same installation, a model querying production data raises a question a prompt cannot answer: who may read what. If access control depended on the model following instructions, rephrasing the question would be enough to get around it.

So the question is translated to SQL, and the server rewrites that query before executing it. A rewriter over the syntax tree injects three filters: client database, session role and action scope.

The filters are injected, not checked afterwards. A query asking for another company's data does not fail validation: it runs already scoped and returns only what is permitted.

## Result

On that base: differentiated access control for developer, administrator and user, sanitisation of sensitive fields, an audit record per query, and retrieval with a relevance floor.

With that floor, a question with no support in the data returns that there is no information. It does not return a text assembled from loosely related fragments.

## What I learned

The first three versions kept part of the visibility control in the prompt. Each rebuild moved one of those decisions into code, until none of them were left in the instruction text.

The practical difference is that the final version can be tested: a test runs the rewriter and checks that the resulting SQL carries all three filters. There is nothing equivalent to execute against a prompt.
